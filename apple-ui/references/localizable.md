# Localizable

When texts are displaying for the user, these texts have to be localizable and translated for supported langugages. Use same supported langugages that other modules if existing otherwise ask user which langugage he wish support for the module or the app.

## General Guidelines
- Use String Catalog
- Check if there is an existing string catalog in the swift pckage local or in the app before creating new one. Always use existing string catalog.
- Localized text using swiftui views. If text is build from multiple values, create a dedicated function in swiftui view or viewmodel.
- First string catalog is named `Localizable.xcstrings`. If add new string catalog because user ask, use a different name but always same extension.

## Create String catalog

If there is no string catalog in main app or module where you add texts, create following this structure:

```
{
  "sourceLanguage" : "en",
  "strings" : {
  },
  "version" : "1.1"
}
```

Below an advanced example of how it look like for english and french supported languages:

```
{
  "sourceLanguage" : "en",
  "strings" : {
    "Alexandre" : {
      "comment" : "A name displayed in the preview.",
      "isCommentAutoGenerated" : true,
      "shouldTranslate" : false
    },
    "Retry" : {
      "comment" : "A button label.",
      "isCommentAutoGenerated" : true,
      "localizations" : {
        "fr" : {
          "stringUnit" : {
            "state" : "translated",
            "value" : "Réessayer"
          }
        }
      }
    },
    "There is %lld cars in your collection" : {
      "comment" : "Information in home screen",
      "localizations" : {
        "en" : {
          "variations" : {
            "plural" : {
              "one" : {
                "stringUnit" : {
                  "state" : "translated",
                  "value" : "There is %lld car in your collection"
                }
              },
              "other" : {
                "stringUnit" : {
                  "state" : "new",
                  "value" : "There is %lld cars in your collection"
                }
              }
            }
          }
        },
        "fr" : {
          "variations" : {
            "plural" : {
              "one" : {
                "stringUnit" : {
                  "state" : "translated",
                  "value" : "Il y a %lld voiture dans votre collection"
                }
              },
              "other" : {
                "stringUnit" : {
                  "state" : "translated",
                  "value" : "Il y a %lld voitures dans votre collection"
                }
              }
            }
          }
        }
      }
    }
  },
  "version" : "1.1"
}
```

## Localization rules (mandatory):

1) Translate ONLY user-facing UI strings (text shown to the user).
   - Examples: button titles, alerts, labels, descriptions, onboarding copy, settings text, empty states, errors shown to users.

2) DO NOT translate:
   - Proper names (people names): Alexandre, John, Maria, etc.
   - Brand/company/product names: Samsung, iPhone, YouTube, TikTok, OpenAI, etc.
   - Place names when used as official names: New York, Paris, etc. (unless the app’s UX requires translation).
   - Identifiers/keys: localization keys, enum/raw values, analytics event names, feature flags, URLs, file names.
   - Technical tokens/placeholders: %@, %d, {value}, {{name}}, \n, markdown, code snippets.
   - Anything inside code identifiers or API names.

3) If a user-facing sentence contains a proper name/brand, translate the sentence BUT keep the proper name/brand unchanged.
   - Example: "Alexandre liked Samsung phones" -> "Alexandre aime les téléphones Samsung"

4) All new or edited user-facing strings must be localized using String Catalog / localized keys.
   - Do not inline hardcoded translated strings in SwiftUI/UIKit.
   - Keep localization keys stable and in English (or existing project convention).

5) Before finishing, verify that:
   - No UI string remains hardcoded (except debug-only logs).
   - Proper names/brands are preserved exactly (no translation, no casing changes).

## Make text localizable

To localize text in swiftUI view use the following structure:

```swift
// Localizable text in a Swift package or framework.
Text("My Collections" bundle: #bundle, comment: "Section title above user-created collections."
```

Add comment only if the text can be ambiguous or misinterpreted.

Use always `Text(:bundle:)` to localized text when possible in swiftUI. For example for buttons:

```swift
Button {
    // action
} label: {
    Text("Hello world!", bundle: #bundle)
}
```

Make general text localizable using the String(localized:) initializer. For apps targeting older platforms, use the NSLocalizedString macro.

```swift
// General localizable text.
String(localized: "Add a description for your collection here.", bundle: #bundle)
```

To refer to the main app, pass Bundle.main, which is also the default bundle.

If string catalog gets too big, ask user if you can create multiple string catalog files within a single Xcode project, and give each a unique name. Then choose which string catalog to use for each translation by passing the string catalog name to the tableName or table parameter to the respective localization API as follows:

```swift
// A SwiftUI localization example pointing to a specific string catalog.
Text("Explore", tableName: "Navigation")


// A general text localization example pointing to a specific string catalog.
String(localized: "Gorgeous mountain peaks!", table: "LandmarkCollectionData")
```

### Add variants for strings that contain plurals

Languages have different grammatical rules for handling plurals of nouns and units. For example, in English, you can return 1 item when the value of %lld is 1. And you can return %lld items for all other cases. Other languages can have fewer or more plural variants, depending on their region and locale.

If there is more than 1 variable in the string, prefer use `%1$lld`, `%2$lld`, etc. Replace `lld` by `@` for string variable value and `lf` for Double variable value.

## Date Formatter

- For date formatter use Date.FormatStyle: A structure that creates a locale-appropriate string representation of a date instance and converts strings of dates and times into date instances. For more details and how to use it `date-formatter.md`.

## Number Formatter

- For number formatter in swift use latest api format style `IntegerFormatStyle`, `FloatingPointFormatStyle`, `Decimal.FormatStyle`. For more details and how to use it `number-formatter.md`.
